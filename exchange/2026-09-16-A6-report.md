## 1. Where the 19% went (measured before any change)

Two runs of `bench/spec-sample-ab.sh` on the unchanged engine
(`643593062a0a9018`, built from `c82fd6f`), one process each, 20 prompts,
n=64, T 0.7 / top_p 0.9 (top_k 0, min_p 0 by the engine's defaults), seeds
1000+i. Megakernel on (`BARO_MEGA: True` echoed) and off (`BARO_MEGA: False`
echoed). 290 W cap, -100 mV, sclk median 3006 and 3033 MHz, junction max 75
and 78 C, queue empty. Receipts `.work/a6/s1-mega/`, `.work/a6/s1-launch/`.

| arm | median tok/s (min-max) | ms/token |
|---|---|---|
| megakernel, T=0 no-spec (the greedy champion shape) | 135.00 (134.63-135.42) | 7.41 |
| launch path (`BARO_MEGA=0`), T=0 no-spec | 107.99 (107.85-108.20) | 9.26 |
| launch path, T=0.7 no-spec | 108.33 (108.01-108.50) | 9.23 |
| megakernel process, T=0.7 no-spec (what A1 measured) | 108.32 (107.95-108.51) | 9.23 |

| component | ms/token | share of the 1.85 ms gap |
|---|---|---|
| megakernel bypass (`mega_req` required `temperature <= 0`) | 1.85 | 100% |
| `amar_sample_row` + `tokcp_k` in place of `amar_argmax_row` | -0.03 (inside the spread) | 0% |
| extra launches, readbacks, host work | none: the T>0 path adds one launch (`tokcp_k`) and no sync | 0% |

The sampler kernel was never on the critical path. `serve/engine.mojo` set
`mega_req = mega and sample.temperature <= 0`, so every sampling request ran
all 32 layers on the per-layer launch path instead of the one-launch
megakernel, and the launch path alone is 20% slower at T=0 (107.99 vs
135.00). The A1 gap (108.32 vs 135.00, 19.8%) reproduces to 0.1%. The brief's
kernel-side hypothesis (KSAMP-c compaction, window width, general path) is
not the cause and was not built.

Spec arms in the same runs: T=0.7 spec 146.89 (megakernel process) / 145.73
(`BARO_MEGA=0`), T=0 spec 149.44 / 148.73, acceptance 0.691 / 0.660, all
matching A1 (147.15 / 150.24). The window never used the megakernel
(`BARO_MEGA_WIN` defaults to 0), which is why spec is flat across the two
processes.

## 2. What changed (`54fb4bb`, host only, 4 lines of logic)

- `serve/engine.mojo`: `mega_req` no longer requires `temperature <= 0`.
  Penalties, top_logprobs and grammar requests still exclude the megakernel
  (their logits edits and mask sit between the head and the draw on the
  launch path; unchanged).
- `serve/window.mojo`: the two `mega_token_*` launches pass `fold_head = 0`
  when `cfg.sample.temperature > 0`, and `head_folded` is false there, so
  the megakernel runs the 32 layers only and the existing launch-path head
  (`rms_m`, `rmsc_k`, `gemm_w`, `r_head`) and the existing sampling branch
  (`amar_sample_row` + `tokcp_k`) run after it. This is the shape
  `mega_win_k` already used for the window; no kernel file was touched.
- T<=0 is byte-for-byte the old path: same launch, `fold_head = 1`, argmax
  inside the megakernel.

The brief's kernel-side levers (KSAMP-c compaction loop, window width,
general path) were not taken: section 1 shows they could not have moved the
number.
