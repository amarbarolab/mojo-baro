## Interface contract (both lanes build against this, verbatim)

File `serve/realign.mojo`:

```mojo
def realign_expected_embedding(
    ctx: DeviceContext,
    mut b: WindowBufs,        # after a step: b.logits_d holds [VOCAB] f32 logits of row 0 (see serve/window.mojo:144-160, 567)
    e_dev: DeviceBuffer[f32], # out: [H] f32, e = softmax(logits) · W_emb
) raises
```

`W_emb` is the token-embedding table already resident in the pack (`embed_k` = `amar_embed_lookup_pos`, `serve/registry.mojo:176`, launched at `serve/window.mojo:166,628` — find the table's buffer/offset/dtype there and in `serve/harness.mojo:load_pack`). Logits for the current row are already computed by the window/megakernel path before `argmax_d` (`serve/window.mojo:275`); REALIGN does not recompute the LM head.

## Item REALIGN — realigned expected-embedding kernel

Files: `serve/realign.mojo` (new), `kernels/realign_kernels.mojo` (new, the GPU kernels: softmax over VOCAB, weighted gather-accumulate over the embedding table into `e[H]`), `kernels/test_realign.mojo` (new), `tools/realign_oracle.py` (new, numpy oracle).

Given: post-norm `h_L` for one row and the pack's logits. Must: `e_dev` equals the numpy oracle `softmax(logits) @ W_emb` (W_emb dequantized the same way `embed_k` reads it) with max-abs error ≤ 1e-3 relative to `max|e|`, on 5 real prompts (`bench/mtp-prompts/p01..p05`, pack `.work/engine-pack-q4`). Also print, for each prompt, the argmax token and the nearest-embedding token of `e` (cosine over W_emb rows); report both, no threshold.

Test: `kernels/test_realign.mojo` built AOT into `.work/test_realign`, run under `gpu-wait run --priority 30 --vram 8 --`. Dump `logits` and `e` to `.work/realign-dump/` as raw f32 and have `tools/realign_oracle.py` compare (it reads the dump and the pack; it never launches the GPU).

Done: test green, oracle diff printed in the report, kernel launch time for one realign step measured and reported (target ≤ 1 ms; report the number either way).

Non-goals: no change to the megakernel, no harness, no bf16 path.

## Item HARNESS — 5-arm dual-engine evaluator

Files: `bench/bench_latent_handoff.mojo` (new), `bench/latent-handoff.sh` (new), `bench/e8_score.py` (new, Python oracle for arithmetic answer extraction + JSON exact-match only; schema validity is checked in Mojo via `grammar/` `Automaton`/`Matcher`), `results/e8/` (output dir; `results/` is tracked).

Start from `bench/bench_hidden_dtype.mojo` (E9: prompt prefill, K latent steps via `step_latent_raw`, receiver ingest, 64-token greedy gen) — copy its structure, do not modify it.

Data: `bench/data/e8_tasks.json` already exists — 40 items, keys `id,type(json|math),prompt_text,full_prompt,tokens,expected,schema_file(json only)`. `tokens` are pre-tokenized Qwythos ids. Use it as-is.

Arms per item (preregistered, do not rename):
- `0`: B answers `full_prompt` alone, greedy.
- `T`: A generates ≤ 300 tokens of chain-of-thought text after the prompt; B receives prompt + that text (tokenize by appending A's generated ids), answers.
- `L8-raw`: A does 8 latent steps feeding raw `h_L` (`b.hn_d`) back (exactly E9's loop); B ingests 8 f32 vectors as prefix embeddings, answers.
- `L8-soft`: same but each fed-back / shipped vector is `realign_expected_embedding(...)` output.
- `L32-soft`: 32 realigned steps.

Co-residency: A and B are TWO engine instances (two `WindowBufs` + two pack loads) resident at once; record VRAM before/after both loads (`gpu-wait gpu` or rocm-smi read-back) in the output. The handoff between A and B is an in-process host copy for this experiment (memfd transport is E7's, already measured) — say so in the output header.

Until REALIGN lands: build against the interface contract above with a local stub file `serve/realign.mojo` containing the signature and a `raise Error("REALIGN not merged")`. The soft arms must abort with that error, never silently fall back to raw. Do not commit the stub in a way that conflicts: keep it as the only content of that file on your branch; the coordinator resolves the merge.

Scoring: `math` → extract the last integer in B's decoded answer (decode ids with `serve/tokenizer.mojo`), exact match to `expected`. `json` → B decodes under the grammar for `schema_file` (see `grammar/test_accept_known_good.mojo` for the API), score = schema-valid AND parsed object equals `expected` (compare via `bench/e8_score.py` on the dumped strings).

Output: `results/e8/<topology>-<date>.json` (per item, per arm: correct, producer_s, receiver_s, generated ids) and a markdown table `results/e8/<topology>-<date>.md`: accuracy per arm per task type, producer time median per arm, VRAM numbers. **Do not compute the gate verdict** — the coordinator does.

Topology 1 (Qwythos-9B q4, `.work/engine-pack-q4`, ~13.3 GB for two) is the gate-defining run and must be built first. Topology 2 (Spark-4B, `.work/spark`, `serve/spark.mojo`): first check whether `WindowBufs`/`step_window`/`hn_d` exist for the Spark engine; if the harness structure does not transfer, write `.work/e8-harness-topology2-blocker.md` (what is missing, LOC estimate) and finish Topology 1 only. Do not build a Spark engine.

Test: `bench/latent-handoff.sh --items 4 --arms 0,T,L8-raw` (smoke, 4 items, no soft arms) under `gpu-wait run --priority 30 --vram 14 --`; must produce both output files and a schema-valid JSON. Full 40-item run is the coordinator's after merge.

Done: smoke green, output files present, report lists the exact command lines, VRAM read-back, and the Topology 2 status.
